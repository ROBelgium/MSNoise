Major:

* added support for Location IDs: TODO + add documentation

Bugfixes:

 - msnoise.core.signal (wavelet / WCT):
  * smoothCFS: fixed a long-standing off-by-one inherited from the original
    MATLAB (``wcoherence``) port. The loop ran over ``range(0, n_scales)`` but
    kept the 1-indexed row access ``cfs[kk - 1]`` while using ``normscales[kk]``,
    so every row was smoothed in time with the scale of the NEXT row, and the
    last (lowest-frequency) row was smoothed with the FIRST (smallest) scale.
    Every row was still written exactly once, so nothing was skipped or
    double-smoothed — only the smoothing width was wrong. Reported in #444.
    IMPACT: Wcoh and WXdt change slightly with respect to any run made before
    this fix. The error is small in the mid-band and grows toward the
    low-frequency end of ``wct_freqmin..wct_freqmax`` (mean |dWcoh| ~ 0.003,
    max ~ 0.10 on a 0.1-8 Hz / nptsfreq=100 / ns=3 / nt=0.25 test case, with
    the largest deviations in the lowest few frequency rows). Published dv/v
    obtained through the wavelet pipeline should be re-run before comparison.
  * apply_wct: the mother wavelet chosen via the ``wavelet_type`` config was
    applied to the reference CWT only — the current-day CWT was hardcoded to
    ``Morlet(6)``. Since scales are derived as ``1/(mother.flambda()*f)``, the
    two CWTs lived on different scale grids. ``mother`` is now carried in the
    tuple returned by prepare_ref_wct and reused by apply_wct. IMPACT: only
    affects projects setting ``wavelet_type`` to something other than the
    default ``('Morlet', 6.)``; those results were wrong and must be re-run
    (self-coherence of a trace with itself dropped to 0.27 for Morlet(4),
    0.006 for Paul(4) and 0.0001 for DOG(2), instead of 1.0).


 - msnoise.core.compute (cross-correlation / whitening / MWCS):
  * mwcs: the cross-spectrum phase is now unwrapped INSIDE the
    ``[freqmin, freqmax]`` measurement band only. It used to be unwrapped from
    DC across the whole padded spectrum before being restricted to the band.
    Below ``freqmin`` a band-passed CCF carries only filter leakage, so the
    phase there is essentially random and ``np.unwrap`` performs a random walk;
    any cycle slip it picks up shifts EVERY in-band phase by a constant 2*pi*k,
    and since the regression is forced through the origin that offset becomes a
    spurious dt of about k/f. This is the mechanism behind isolated MWCS
    outliers. On a synthetic 1-4 Hz test with a known dt = 20 ms, 13.4% of
    windows were off by more than 10 ms (worst case 0.76 s); after the fix, 0%
    (worst case 20.4 ms). The median is unchanged, so only the outliers are
    removed. Anchoring on the first in-band bin assumes |dt| < 1/(2*freqmin)
    (0.5 s for freqmin = 1 Hz), verified numerically — orders of magnitude
    above any dv/v measurement. IMPACT: dv/v time series computed through
    mwcs/mwcs_dtt lose their spurious spikes; well-measured windows are
    unaffected.
  * mwcs: the frequency axis and band index are now built once before the
    window loop instead of per window, and a band containing fewer than two
    FFT bins raises a clear ValueError naming the bin width and mwcs_wlen
    instead of failing later with "`ydata` must not be empty!".
  * mwcs: replaced a "last window was too small" warning that could never fire
    (the loop exits as soon as maxind > len(current)) with a debug message
    reporting the number of trailing samples actually dropped.
  * whiten2, whitening_type=PSD: the 5th/95th percentiles, the outlier mask
    and the clip were all applied to the COMPLEX spectrum. NumPy resolves these
    lexicographically on the real part without raising, and np.clip() replaced
    every out-of-range bin by the real scalar +/-rms — zeroing the imaginary
    part and destroying the phase of exactly the bins the spike suppression
    targets. Percentiles and clipping now act on the magnitude and preserve
    arg(X), as the docstring always described. IMPACT: whitening_type=PSD
    results were wrong and must be re-run; B (default) and HANN are unaffected.
  * whiten2, whitening_type=PSD: removed a stray ``taper *= taper`` that made
    the PSD-branch spectral window cos^4 while whiten() and the brutal branch
    use cos^2. IMPACT: slightly wider effective passband for PSD whitening.
  * whiten / whiten2: the Hermitian-symmetry assignment assumed an even Nfft
    and left the first negative-frequency bin unset for odd Nfft (next_fast_len
    can return 9, 15, 25, 27, 45, 75, 81, 125 ...). Rewritten in terms of
    (Nfft-1)//2 so it is correct for both; whiten()'s positive-frequency vector
    was extended for the same reason.
  * whiten: an empty passband now raises a ValueError naming the band, the bin
    width and the Nyquist frequency instead of an IndexError on ``J[0]``.
  * myCorr2: the ``maxlag == Nt`` branch sized the output buffer at 2*Nt while
    the folded CCF is 2*Nt-1 samples, so it raised a broadcast error. The
    branch is gone; maxlag is clamped to Nt-1 with a warning and a single code
    path is used throughout.
  * myCorr2, pcc_xcorr: documented the amplitude-scale conventions — myCorr2
    divides by nfft twice (once inside ifft), so CCF amplitude scales as
    1/nfft^2 and depends on the per-window npts; pcc_xcorr uses the fixed 1/N
    biased estimator, giving a (N-|lag|)/N triangular taper across the lag
    window. No numerical change.

 - msnoise.s03_compute_no_rotation:
  * the PSD used by whitening_type=PSD is now computed from the array that is
    actually whitened (winsorized + cosine-tapered) rather than from the
    untouched ObsPy trace, and welch is called with nperseg=npts, nfft=nfft so
    it zero-pads to the expected nfft//2+1 bins instead of silently clamping
    nperseg (which would have returned npts//2+1 bins and misaligned the
    division inside whiten2).

Changes:
 - msnoise
  * drop Continuous Integrations for Python 2.7. Only test on 3.7, 3.8 and 3.9
  * support for Location codes: TODO
  * PostgreSQL support

 - msnoise.admin:
  * changed the visualisation of the config table, allows filtering names,
    shows modified/new values, definition and enum values
  * when a type or enum is defined, the field in the Edit Form view is set to a
    select box/date picker to avoid wrong choices.

 - msnoise.api:
  * preload_instrument_response now reads anything
    obspy.inventory.read_inventory can read
  * preload_instrument_response() returns either a pandas.DataFrame or and
    Inventory object (should eventually be default)
  * get_next_job() now allows setting a max number of returned job (useful
    when processing many stations/pairs for a limited number of days in
    parallel on multiple cores).
  * get_results() TODO
  * get_results_all() now returns an empty DataFrame if there are no data
  * check_stations_uniqueness(): helper function to determine if a station
    that was provided is lacking the location code. If there is only one
    possible case, returns it, otherwise #TODO fails.

 - msnoise.commands
  * execute: allows to export the result of a SELECT query to a CSV dataframe
  * update_loc_chan: updates the `used_location_codes` and `used_channel_names`
    from the SEED IDs available in the database, for each NET.STA (station
    table)

 - msnoise.compute_cc
  * added possibility to echange the clipping (winsorizing) and spectral
    whitening steps using the new `clip_after_whiten`. Note: requires an extra
    pair of ifft/fft on the whitened data if set to Y.
  * added the possibility to normalise individual CCFs (individual windows, of
    `corr_duration` duration, either by the power of the input traces, by the
    maximum of the CCF or by its absmax.

 - msnoise.compute_mwcs:
  * the code now gets the ref and current data from the API and don't do I/O
    directly. TODO this will allow replacing the storage format without changing
    the code of the different steps.

 - msnoise.default:
  * now the default config bits are stored in a CSV file, with name, default
    value, definition, type, and enum values
  * the default.default dict is an AttribDict containing all information
  * deprecated bits: "autocorr", TODO: response_format?

 - msnoise.doc:
  * added how-to for checking the instrument response
  * TODO add documentation for the QC package

 - msnoise.new_jobs:
  * added support for LOC IDs
  * if a Station has multiple `used_location_codes` defined, those will be
    treated like different stations. E.g. if we have 2 stations: BE.UCC and
    BE.MEM BE.MEM has "00,10" configured, and data has been found for those LOC
    by scan_archive, the new_jobs step will create three cross-station jobs:
    BE.MEM.00:BE.MEM.10, BE.MEM.00:BE.UCC.--, BE.MEM.10:BE.UCC:--

 - msnoise.plots:
  * all plots have been adapted to fetch NET.STA.LOC(.CHAN)
  * if the LOC code is not provided for a plot, the API checks if there is only
    one solution and returns it, otherwise fails.
  * data_availability: now shows the availability for each SEED id present in
    the database
  * distance: TODO: check interstation distances for different LOC

 - msnoise.preprocessing:
  * replaced "stream.simulate" by "stream.remove_response"
  * added supoort for the LOC IDs

 - msnoise.qc: #TODO ALL DOCUMENTATION PAGES
  * new group, commands (TODO temporary naming): compute_psd, plot_psd
  * computes PPSD using obspy, saves daily NPZ and PNG files in SDS-like
    structure
  * new parameters in the database (PSD length, overlap, and smoothing
    parameters, see obspy's doc for PPSD.__init__)
  * added documentation TODO

- msnoise.scan_archive:
  * added support for the LOC IDs. If it is "" (=empty), the record is added to
    the data_availability table with the "--" loc value.
  * the scan procedure will apply the global network and channel selectors (from
    the config table), then apply the per-station selectors defined in
    `used_location_codes` and `used_channel_names`. If empty, scan_archive will
    scan all possible ("*") LOC IDs and add them to the database.

 - msnoise.table_def:
  * Station: get new fields: `used_location_codes` and `used_channel_names`
  * Filter: TODO remove the rms_threshold parameter
